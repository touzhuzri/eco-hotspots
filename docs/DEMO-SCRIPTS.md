# 世界树 · 2–3 分钟演示脚本

三个场景串成一条线：**数据探索 → RAG 溯源 → 多模态 + Agent**。每个场景约 40–60 秒，总时长控制在 2.5 分钟以内。

演示前检查：

- 服务已启动：`./start.sh status`
- `/api/ai/health` 返回 `"ok": true`、`"hasKey": true`
- 知识库面板显示已向量化（`BAAI/bge-m3`，1024 维）
- 浏览器缩放 100%，关闭无关标签页
- 如需识图，准备 `demo/quercetin.png` 或一张植物/结构式照片

---

## 场景 1：数据探索（约 45 秒）

**目的**：证明 AI 不是聊天框，而是能查 LOTUS、画图、驱动 3D 场景。

**操作**：

1. 打开网站，等世界树入场完成。
2. 点底部 AI 坞，输入：

```text
哪个科的黄酮最多？画分布图，并带我去看。
```

3. 观察工具轨迹：

```text
查询 LOTUS → 生成图表 → 场景动作
```

4. 图表出现后，点「带我去看」确认按钮，镜头聚焦到对应分子。

**讲解话术**：

> 这个问题不是模型凭记忆回答的。它先调用 query_molecules 查 LOTUS 260413，再按来源科聚合，最后生成图表；点确认后，场景动作才真正执行。数字和 3D 定位都有数据出处。

**兜底**：如果模型没有自动调场景动作，补一句：

```text
把刚才的结果在世界树里定位一下。
```

---

## 场景 2：RAG 溯源（约 50 秒）

**目的**：证明回答能引用知识库段落 / DOI，并和 LOTUS 数据交叉核对。

**操作**：

1. 点 AI 坞「知识库」→ 上传一篇天然产物论文或课程资料（PDF / Word）。
2. 等状态变成「已向量化」。
3. 打开「研究」模式，输入：

```text
请总结这份资料里关于黄酮的内容，并和 LOTUS 数据核对；如果资料和 LOTUS 数字不一致，请指出差异。给我可核对的出处。
```

4. 观察：

```text
计划 → 检索知识库 → 查询 LOTUS → 反思 → 结论
```

5. 点「导出研究简报」，展示 Markdown 里的「研究计划 / 结论 / 研究反思 / 工具记录 / 来源」。

**讲解话术**：

> 它不是把整篇 PDF 塞给模型，而是先切块、向量化、检索最相关段落；回答里会标《文件名》第 N 段。涉及数量时再调用 LOTUS 工具核对。最后的研究简报把计划、工具记录、来源和局限都导出，方便复查。

**兜底**：如果上传文档解析失败，改用内置 LOTUS 数据集卡片：

```text
LOTUS 数据集卡片里对数据局限性是怎么写的？请给出原文段落，并说明哪些问题 LOTUS 不能回答。
```

## 场景 3：多模态 + Agent（约 60 秒）

**目的**：证明图片不是附件，而是结构化抽取后自动进入 LOTUS 工具链。

**操作**：

1. 点「识图」，上传 `demo/quercetin.png` 或一张植物照片。
2. 输入：

```text
这是什么？如果是植物，判断可能的科；如果是结构式，识别可能的分子。然后查 LOTUS、找相似分子，并给出不确定性。
```

3. 观察：

```text
图像结构化卡片
→ 查询 LOTUS
→ 相似分子
→ 分类分布图
→ 场景定位
→ 结论 + 研究反思
```

4. 指出图像卡片里的字段：

```text
图像类型 / 主体 / 科属候选 + 置信度 / 分子候选 + 置信度 / 不确定项
```

**讲解话术**：

> 视觉模型只负责抽取候选，不直接下结论。候选带置信度，低于阈值的不会自动查库；服务端再拿候选去查 LOTUS、找相似结构、画分类分布。图片里的文字也不会被当成指令执行。最后回答会明确写出哪些地方不确定。

**兜底**：如果视觉模型不可用，改演示文献检索：

```text
检索 quercetin 近五年的论文，优先 Nature，给出标题、期刊、年份和 DOI；知网/万方/WoS 请给检索入口。
```

---

## 收尾话术（约 15 秒）

> 世界树把 22.7 万条 LOTUS 天然产物结构做成可探索的 WebGL 星点树；AI 层负责查数据、检索知识库、读论文、识图、画图和驱动 3D。所有数字必须走工具，所有结论尽量给出来源；知网/万方/WoS 需要机构权限的内容，我们只给检索入口，不抓取受限全文。
